## 事件摘要
程式無法自動判定我們是否受影響，需要人工確認；可先檢查資料庫或管理工具是否可被直接連上、對外系統是否有未修補漏洞，以及委外廠商是否持有我們的資料。

## 不受影響與需確認
- 需確認：*：人工判斷事件的攻擊手法是否適用於我們的系統；把事件對應到 controls.yaml 的控制項；沒有合適的就建議新增；建議新增控制項：後端API須獨立驗證身分與授權，不得僅依賴前端控管
  - （推測）資料庫或資料庫管理工具可以從外部或其他環境直接連線；查：確認存放個資與訂單的資料庫及資料庫管理工具，只允許必要的來源連線；系統：App 雲端檔案儲存區、正式會員資料庫、正式訂單資料庫、訂單匯出檔案儲存區、資料庫網頁管理工具
  - （推測）經由網站或 API 的漏洞（例如注入、越權）大量讀取資料庫內容；查：檢查對外網站與 API 是否有注入或越權問題，以及是否出現大量讀取；系統：API 閘道、商店網站
  - （推測）對外系統有未修補的漏洞被利用；查：列出對外系統與元件版本，對照近期安全公告並排定修補；系統：API 閘道、內部營運工具、行銷官網、辦公室 NAS、商店網站
  - （推測）委外服務商自己的系統被入侵，我們交給它的客戶資料一起外流；查：盤點我們交給委外商的資料欄位與筆數，確認對方是否已通知、資料是否已最小化；系統：寄信服務、未登記的架站服務
