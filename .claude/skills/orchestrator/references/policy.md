# Orchestrator 核准政策（由 scripts/build-agent-plan-reference.py 依 agents/tools/orchestration.py 產生，請勿手改）

派工（dispatch）與驗收（review）的提案都是給程式核准的**建議**：必要任務一定照跑，只能追加任務與排優先，
不能要求跳過、停用或改變任何評估、分數與結論。程式依本次資料逐項檢查，不合規則的項目會被拒絕並記錄原因；
被拒絕的項目不佔配額。

共同規則：
- 提案是一個 JSON 物件；所有欄位都可以省略，沒有建議時寫 `{}`
- 只允許下面列出的欄位；頂層多寫的欄位各記一筆拒絕，某一項多寫欄位會讓整項被拒絕
- 每項理由 1 句，最多 120 字
- 只能使用輸入檔裡出現的事件 ID、風險 ID 與控制項 ID；候選清單是程式算的參考，最終資格以程式核准為準

## 派工（dispatch）

```json
{"extra_controls": [{"event_id": "事件 ID", "control_id": "C-...", "reason": "1 句理由"}],
 "extra_tasks": [{"agent": "a4", "subagent": "impact-analyst", "event_id": "事件 ID", "reason": "1 句理由"}],
 "priorities": [{"agent": "a4", "risk_id": "風險 ID", "reason": "1 句理由"}]}
```

- `extra_controls`：值得一併確認的控制項。只列出本次已算好的檢查結果，不影響判定；事件已直接對應的控制項不要重複
- `extra_tasks`：追加任務，對象由程式挑選（只挑輸入中有候選對象的事件）
- `priorities`：把 A4 必要任務中的風險移到說明順序最前面，不新增也不移除風險

可追加的任務：

| agent | subagent | 對象 | 用途 |
|---|---|---|---|
| a2 | dependency-analyst | 事件（event_id） | 依事件解讀相同產品的套件漏洞（程式挑選項目，最多 12 項） |
| a2 | runtime-analyst | 事件（event_id） | 依事件解讀相同產品的執行環境與支援期限（程式挑選項目，最多 12 項） |
| a3 | retro-hunter | 事件（event_id） | 回溯搜查事件日期前 7 天到現在、相關系統的登入與資料庫紀錄（只限每日與情境；公告調查本來就會跑） |
| a4 | impact-analyst | 事件（event_id） | 說明與此事件相關的風險影響（程式挑選風險，每件最多 3 個） |

上限：
- 只處理日期最新的 5 件新同業事件（公告調查只處理本次公告）
- 每件事件最多 3 個加查控制項，總共最多 8 個
- 追加任務總共最多 5 項（A2 每項最多 12 個項目、A3 最多 5 個系統、A4 每件最多 3 個風險，由程式挑選）
- 排優先最多 5 項，只限 A4 必要任務的前 10 個高風險

## 驗收（review）

```json
{"extra_tasks": [{"agent": "a5", "subagent": "intel-report-writer", "event_id": "事件 ID", "reason": "1 句理由"},
                 {"agent": "a5", "subagent": "key-rotation-advisor", "risk_id": "風險 ID", "reason": "1 句理由"}],
 "priorities": [{"agent": "a5", "risk_id": "風險 ID", "reason": "1 句理由"}],
 "summary": "執行摘要"}
```

- `extra_tasks`：A5 的後續任務。事件目標的任務給 `event_id`，風險目標的任務給 `risk_id`，不要兩個都給
- `priorities`：調整 A5 解法清單與 CEO 摘要參考清單的順序，不新增也不移除風險
- `summary`：給工程團隊的執行摘要，繁體中文，最多 300 字；不寫金鑰、Token、個資、檔案路徑、IP、連接埠、設定鍵或控制項 ID，
  含這些內容會整段拒絕

可追加的任務：

| agent | subagent | 對象 | 用途 |
|---|---|---|---|
| a5 | brand-notice-writer | 事件（event_id） | 為受影響、但程式未要求通知的事件撰寫通知草稿（另外標示，不改變是否需要通知） |
| a5 | intel-report-writer | 事件（event_id） | 為需確認的事件撰寫情資報告摘要 |
| a5 | key-rotation-advisor | 風險（risk_id） | 為本次事件相關、必要任務沒有涵蓋的金鑰風險撰寫輪替建議 |

上限：
- 追加任務總共最多 3 項
- 排優先最多 5 項，只限 A5 解法清單（前 12 個）與 CEO 摘要參考清單（前 5 個）中的風險

## 拒絕原因

| 原因 | 什麼時候 |
|---|---|
| 只能追加，不能關閉或改變必要評估 | 頂層有規定以外的欄位，或某一項多寫了欄位（整項拒絕，不會移除欄位後核准） |
| 欄位缺漏或格式不符 | 缺少必要欄位，或欄位不是字串 |
| 事件不在本次範圍 | 事件不在本次範圍（每日與情境：最新的 5 件新同業事件；公告調查：本次公告） |
| 不在控制項清單 | 控制項 ID 不在控制項清單 |
| 事件已對應此控制項 | 事件已經直接對應這個控制項 |
| 不在可追加的工作清單 | agent 與 subagent 不在本模式可追加的任務清單 |
| 沒有符合條件的對象 | 程式依本次資料挑不出可以處理的對象 |
| 必要任務已包含 | 必要任務已經包含這項工作 |
| 不在可排優先的清單 | 排優先的風險不在可排優先的清單，或 agent 不對 |
| 事件不是需確認 | 事件不是需確認 |
| 不是本次相關的金鑰風險 | 風險不是本次事件相關、必要任務沒有涵蓋的金鑰風險 |
| 程式已要求通知 | 程式已經要求這件事件發通知 |
| 摘要含不允許的內容 | 執行摘要含金鑰、個資、檔案路徑、IP、連接埠、設定鍵或控制項 ID 等不允許的內容 |
| 缺少理由 | 理由空白 |
| 重複的建議 | 同一項重複提出 |
| 超過上限 | 超過數量或字數上限（被拒絕的項目不佔配額） |
